# @local/model-alias — 模型别名

给同一个标准厂商（OpenAI、Anthropic、Moonshot、Zhipu 等内置目录厂商）配置**多个 API Key**，并用**别名**区分。

## 背景

DSH 内置「设置 → 模型」页在添加模型时，「标准厂商」列表只显示**尚未配置**的厂商；某厂商配置过一次后即从列表消失（全部配置完后该标签直接禁用）。这是内置页的有意设计（一个厂商一个 profile），但换新 Key、多账号等场景就没了入口。

本插件新增一个设置页「**模型别名**」（紧随「模型」之后）：

- 厂商下拉框**始终列出全部标准厂商**（已配置的带「已配置」标记，仍可选）；
- **别名**写入路由的 `displayName`，就是模型选择器里显示的名字；
- **独立 API Key** 存在该路由派生的凭据引用下（如 `OPENAI_WORK_API_KEY`）；
- 接口地址按厂商目录自动预填；协议按厂商猜测（Anthropic → `anthropic-messages`，Google → `google-generative-ai`，其余默认 `openai-completions`），可改；
- 模型列表支持**从厂商拉取**（用刚输入的 Key）或手动填写；
- 创建后的路由与「第三方模型提供商」同构：出现在内置「模型」页（带「自定义」标签）和模型选择器里（以别名单独成组）。

## 使用

1. **设置 → 模型别名 → 添加别名**；
2. 选厂商 → 填别名（路由 ID 自动生成，可改）→ 核对接口地址与协议 → 粘贴新 Key；
3. 「获取模型列表」或手动补模型 ID → **创建**；
4. 切换 Key/编辑：列表中该行「编辑」；「删除」会同时清掉该路由与其密钥。

## 安装

```sh
dsh plugin --profile web add ~/.local/share/dsh-plugins/model-alias
# 或 设置 → 插件 → 添加插件 选择本目录
```

## 数据位置

- 路由配置：settings 文档 `llm-pi-ai` 段用户层（`providers.<路由ID>`），与内置页同源；
- 密钥：凭据服务（`credentials/set`）。

卸载插件只移除设置页入口，已声明的路由继续由 pi-ai 适配器服务；要彻底移除某条别名，请先在页内删除。

## 已知限制

- 仅覆盖 pi-ai 家族（标准 Key 厂商）；DeepSeek 官方与账号登录不适用；
- 路由 ID 创建后不可改（改名=删除重建）；
- 只读部署下页面全部写操作禁用；
- 编辑模型列表时会保留本表单未管理字段（`reasoningEfforts`、`compat` 等），但不会展示/编辑它们——如需调整请在内置「模型」页的该路由编辑器里操作。
